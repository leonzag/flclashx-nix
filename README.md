# FlClashX для NixOS

Flake с бинарным пакетом [FlClashX](https://github.com/pluralplay/FlClashX)
и модулем NixOS для работы GUI и TUN. Использует официальный `.deb`
версии **0.4.2**, без компиляции приложения и патчей исходного кода.
Поддерживается `x86_64-linux`.

## Зачем нужен этот репозиторий

Запустить GUI на NixOS недостаточно для работы TUN: ядру нужны привилегии
для создания сетевого интерфейса и настройки маршрутов. В FlClashX 0.4.2
Linux-авторизация устроена через setuid: приложение проверяет, что
`FlClashCore` принадлежит root и имеет этот бит, а при отсутствии прав
пытается установить их через `sudo chown` и `chmod`.

Это несовместимо с обычной установкой в `/nix/store`: хранилище неизменяемо,
и приложение не может менять права установленного ядра. При этом GUI
ищет `FlClashCore` рядом со своим исполняемым файлом. Отдельный wrapper
в `/run/wrappers/bin` не меняет этот путь, а capabilities сами по себе
не удовлетворяют проверке setuid в приложении.

Репозиторий появился, чтобы использовать официальный бинарный релиз
с TUN на NixOS, сохранив штатный механизм авторизации FlClashX
и управляя установкой через конфигурацию системы.

Модуль:

- Адаптирует ELF-файлы и библиотечные зависимости для NixOS, сохраняя
  комплектные библиотеки Flutter, плагины и ресурсы.
- Устанавливает управляемую копию приложения в `/opt/FlClashX`.
  Только ядро получает `root:root` и права `4755`; GUI работает от обычного
  пользователя. Файлы установки доступны для записи только root.
- Добавляет TUN-интерфейс в доверенные интерфейсы firewall: весь входящий
  с него трафик разрешается. Глобальная настройка reverse-path filtering
  не изменяется.

Логика upstream: [поиск ядра](https://github.com/pluralplay/FlClashX/blob/v0.4.2/lib/common/path.dart)
и [проверка прав и авторизация](https://github.com/pluralplay/FlClashX/blob/v0.4.2/lib/common/system.dart).

## Установка

Добавьте input в `flake.nix` конфигурации NixOS:

```nix
inputs.flclashx = {
  url = "github:leonzag/flclashx-nix";
  inputs.nixpkgs.follows = "nixpkgs";
};
```

Подключите модуль на нужном хосте. Пример предполагает, что `inputs`
передан модулям через `specialArgs = { inherit inputs; };` в `nixosSystem`:

```nix
{ inputs, ... }:
{
  imports = [ inputs.flclashx.nixosModules.default ];
  programs.flclashx.enable = true;
}
```

Overlay не требуется. Закройте FlClashX перед применением конфигурации:

```bash
sudo nixos-rebuild test --flake .#hostname
flclashx
```

Замените `hostname` именем своей конфигурации. Проверьте GUI и TUN,
затем примените её постоянно через `nixos-rebuild switch` с теми же аргументами.
Установка в `/opt` выполняется модулем NixOS; одного `nix run` недостаточно.
На файловой системе с `nosuid` повышение привилегий ядра не работает.

## Настройки

```nix
programs.flclashx = {
  enable = true;
  autostart = true;          # по умолчанию
  tunInterface = "FlClashX"; # должно совпадать с именем TUN в приложении
  # package = ...;          # переопределение подготовленного пакета
};
```

Для ручного запуска используйте `flclashx`: launcher подготавливает
окружение GTK и GPU-драйвера. Системный автозапуск располагается
в `/etc/xdg/autostart/FlClashX.desktop`. Если осталась пользовательская
запись `~/.config/autostart/FlClashX.desktop` от прежней установки,
удалите её: она может перекрывать системную.

## Обновление и откат

Закройте FlClashX, затем в конфигурации NixOS выполните:

```bash
nix flake update flclashx
sudo nixos-rebuild switch --flake .#hostname
```

Версия приложения закреплена в `package.nix`. Обновление input получает
изменения этого репозитория; новый релиз FlClashX появится после обновления
`version` и SHA-256 `.deb` в пакете. Встроенное обновление ядра не используется,
поскольку установка принадлежит root.

Сервис `flclashx-install` заменяет копию в `/opt` при смене пакета
и удаляет её при отключении модуля. Откат к предыдущей конфигурации
восстанавливает соответствующий пакет. Профили и настройки пользователя
хранятся отдельно и не удаляются. Пакет и его зависимости в `/nix/store`
остаются привязаны к системной генерации и защищены от сборки мусора.

## Проверки

```bash
nix flake check --no-write-lock-file -L
sudo python3 tests/test_install.py
```

Проверяются сборка пакета, ресурсы и зависимости, установщик и его работа
с правами, обновлениями и удалением. GUI, TUN и работу GPU проверяют
на целевой машине.
